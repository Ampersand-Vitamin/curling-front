# AI 디자이너 매칭 — 접근 방식 비교

## 배경

사용자가 헤어 이미지를 업로드하면 유사한 포트폴리오를 가진 디자이너를 추천하는 기능.
어떤 방식으로 "유사하다"를 판단할 것인가에 대한 의사결정 문서.

---

## 1. 태깅 + Vision AI → 자체 데이터로 파인튜닝

### 방식

```
[MVP] 이미지 → Claude/GPT-4o Vision → 태그 추출 → 태그 매칭
                                        ↓
                              (이미지, 태그) 쌍이 자동 축적
                                        ↓
[v2]  데이터 1만 장+ 쌓이면 → 자체 분류 모델 파인튜닝 → API 의존 제거
```

### 장점

- MVP를 가장 빠르게 출시 가능 (프롬프트만 작성하면 됨)
- 데이터셋 라이선스 문제 없음 (자체 데이터)
- 태그 체계 변경이 쉬움 (프롬프트 수정만으로 가능)
- 매칭 이유를 유저에게 설명 가능 ("웜톤 + 레이어드 일치")
- 파인튜닝 전환 시 완전한 자체 모델 보유 가능

### 단점

- MVP 기간 동안 API 비용 발생 (이미지당 ~$0.01)
- Vision AI 응답 속도 1~3초 (파인튜닝 모델은 수십ms)
- 동일 이미지에 대해 태그가 달라질 수 있음 (일관성 문제)
- 파인튜닝 전환까지 외부 API에 의존 (서버 장애 리스크)
- 파인튜닝까지 데이터 축적 기간 필요 (최소 수천 장)

### 비용 예상

| 단계 | 비용 |
|---|---|
| MVP (유저 100명/일) | 월 ~$30 |
| 성장기 (유저 1,000명/일) | 월 ~$300 |
| 파인튜닝 전환 후 | API 비용 0, 서버 비용 월 $5~50 |

### 리스크

| 리스크 | 확률 | 영향 | 대응 |
|---|---|---|---|
| API 비용이 예상보다 높음 | 중간 | 중간 | 캐싱, 요청 제한으로 완화 |
| Vision AI 서버 장애 | 낮음 | 높음 | Claude/GPT 이중화 |
| 태그 일관성 부족 | 중간 | 낮음 | 결과 캐싱, temperature 0 설정 |
| 파인튜닝 데이터 부족 | 낮음 | 중간 | 유저 수가 적으면 전환 시점만 늦어질 뿐 |

### 적합한 경우

- 빠른 MVP 출시가 우선인 경우
- 라이선스 리스크를 원천 차단하고 싶은 경우
- 장기적으로 자체 모델 보유를 원하는 경우

## 2. 태깅 + 오픈소스 데이터셋 + 파인튜닝

### 방식

```
K-Hairstyle 등 공개 데이터셋 (50만 장, 태그 포함)
    ↓
분류 모델 파인튜닝 (ResNet, ViT 등)
    ↓
자체 헤어 분류기: 이미지 → 태그
    ↓
태그 매칭
```

### 장점

- 대규모 학습 데이터 확보 (K-Hairstyle 50만 장)
- 전문가가 태깅한 고품질 라벨 (한국 헤어 디자이너)
- API 의존 없음 (자체 모델)
- 빠른 추론 속도 (수십ms)
- 한번 학습하면 추가 비용 거의 없음
- 헤어 도메인 특화 분류 가능

### 단점

- 라이선스 제한 (K-Hairstyle: CC BY-NC, 상업 불가)
- 한국인 데이터 편향 (우리 서비스는 외국인 우선)
- 파인튜닝에 ML 엔지니어링 역량 필요
- 태그 체계 변경 시 재학습 필요
- 모델 학습 환경 셋업 필요 (GPU)
- MVP까지 시간 소요 (데이터 준비 + 학습 + 검증)

### 비용 예상

| 항목 | 비용 |
|---|---|
| 데이터셋 | 무료 (연구용) / 상업 라이선스 별도 협의 |
| GPU 학습 (Google Colab 등) | 1회 $10~50 |
| 모델 호스팅 | 월 $5~50 |
| 상업 라이선스 (필요 시) | 미정 (협의 필요) |

### 리스크

| 리스크 | 확률 | 영향 | 대응 |
|---|---|---|---|
| **라이선스 위반 적발** | 낮음 | **매우 높음** | 상업 라이선스 사전 확보 or 사용 안 함 |
| 한국인 데이터 편향 → 외국인 정확도 낮음 | 높음 | 높음 | 추가 데이터셋 조합, 서비스 데이터 보강 |
| 파인튜닝 실패 (정확도 부족) | 중간 | 중간 | 하이퍼파라미터 조정, 데이터 증강 |
| 태그 체계 변경 필요 시 재학습 부담 | 중간 | 중간 | 초기 태그 설계를 신중하게 |
| 투자 유치 시 데이터 출처 실사 | 중간 | 높음 | 라이선스 문서화 필수 |

### 적합한 경우

- ML 엔지니어링 역량이 있는 팀
- 라이선스를 해결할 수 있는 경우
- 대상 유저가 한국인 위주인 경우

## 3. 벡터 임베딩 (CLIP 등)

### 방식

```
이미지 → CLIP 모델 → 벡터(512차원)
    ↓
DB에 저장된 포트폴리오 벡터와 cosine similarity 비교
    ↓
가장 유사한 포트폴리오의 디자이너 반환
```

### 장점

- 태그 체계 설계 불필요 (이미지 전체를 "느낌"으로 비교)
- 태그로 표현 못 하는 뉘앙스(분위기, 질감)까지 포착
- UX가 가장 단순 (업로드 → 바로 결과)
- CLIP 로컬 실행 시 무료
- 오매칭 문제 적음 (브라운 ↔ 실버 자연스럽게 분리)

### 단점

- **"왜 유사한지" 설명 불가** (유저에게 "93% 유사"만 보여줌)
- 헤어 세부 스타일(레이어드 vs 보브) 구분 약함 (범용 모델 한계)
- 포트폴리오 데이터가 적으면 결과 품질 낮음
- 배포 시 CLIP 호스팅 필요 (HF API 또는 별도 서버)
- 벡터 DB 운영 필요 (pgvector 등)
- 데이터 적을 때 태깅보다 유저 만족도 낮을 수 있음

### 비용 예상

| 항목 | 비용 |
|---|---|
| CLIP 로컬 (개발) | 무료 |
| HF Inference API (배포) | 무료 티어 월 30만 호출 |
| Supabase pgvector | 무료 티어 내 가능 |

### 리스크

| 리스크 | 확률 | 영향 | 대응 |
|---|---|---|---|
| 헤어 세부 구분 정확도 부족 | 높음 | 높음 | 헤어 특화 임베딩 모델 탐색 |
| 데이터 부족 시 결과 불만족 | 높음 | 중간 | 최소 500장 이상 확보 후 도입 |
| 매칭 이유 설명 불가 → 유저 불신 | 중간 | 중간 | 태깅과 하이브리드로 보완 |
| HF API 무료 티어 제한 | 낮음 | 낮음 | 유료 전환 or 자체 호스팅 |

### 적합한 경우

- 포트폴리오 데이터가 충분히 쌓인 상태 (500장+)
- "분위기" 기반 매칭이 중요한 경우
- 태깅과 하이브리드로 쓸 경우

## 4. 기타 접근 방식

### 4-1. 하이브리드 (태깅 + 벡터)

```
이미지 → 태그 추출 + 벡터 임베딩 동시 수행
    ↓
태그로 후보 필터링 (색상, 길이 등 필수 조건)
    ↓
벡터 유사도로 최종 정렬 (뉘앙스 기반)
```

- 장점: 두 방식의 장점을 모두 가짐 (설명 가능 + 뉘앙스 포착)
- 단점: 구현 복잡도 높음, 두 시스템 모두 유지 필요
- 적합: 서비스가 성숙하고 데이터가 충분할 때 (v2~v3)

### 4-2. 유저 직접 태깅

```
유저가 이미지 업로드 + 직접 태그 선택
    ↓
태그 매칭
```

- 장점: AI 불필요, 비용 0, 가장 정확 (유저 의도 반영)
- 단점: UX 번거로움, 유저가 헤어 용어를 모를 수 있음
- 적합: AI 보조 + 유저 수정 조합으로 사용 시

### 4-3. 텍스트 검색

```
유저가 "웜톤 미디엄 레이어드" 텍스트 입력
    ↓
CLIP 텍스트 임베딩 → 이미지 벡터와 비교
```

- 장점: 이미지 없이도 검색 가능, CLIP이 텍스트↔이미지 매칭 지원
- 단점: 유저가 정확한 용어를 알아야 함
- 적합: 이미지 업로드의 보조 기능으로

## 종합 비교

| 기준 | 1. Vision AI→파인튜닝 | 2. 오픈소스+파인튜닝 | 3. 벡터 임베딩 |
|---|---|---|---|
| **MVP 속도** | 빠름 | 느림 | 중간 |
| **초기 비용** | API 비용 (낮음) | GPU 학습 (1회) | 무료~낮음 |
| **장기 비용** | 파인튜닝 후 무료 | 무료 | HF API or 호스팅 |
| **헤어 분류 정확도** | 중간 | 높음 | 낮음 |
| **설명 가능성** | 높음 (태그) | 높음 (태그) | 없음 |
| **라이선스 리스크** | 없음 | 있음 (CC BY-NC) | 없음 |
| **데이터 편향** | 없음 | 한국인 편향 | 없음 |
| **ML 역량 필요** | 낮음→중간 | 높음 | 낮음 |
| **확장성** | 높음 | 높음 | 중간 |

## 추천

### MVP (지금)

**방식 1: Vision AI 태깅**

이유:
- 가장 빠르게 시작 가능
- 라이선스 리스크 없음
- 서비스 운영하면서 자연스럽게 학습 데이터 축적
- 외국인 헤어에도 바로 동작 (범용 모델)

### v2 (데이터 축적 후)

**방식 1의 연장: 자체 데이터로 파인튜닝**

전환 시점: 태깅된 이미지 1만 장 이상 축적 시
결과: API 의존 제거, 비용 0, 속도 향상

### v3 (서비스 성숙기)

**방식 4-1: 하이브리드 (태깅 + 벡터)**

태그로 필터 + 벡터로 뉘앙스 정렬
최고 품질의 매칭 결과
