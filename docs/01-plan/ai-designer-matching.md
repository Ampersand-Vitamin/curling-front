# AI 헤어 이미지 기반 디자이너 매칭 — 계획서

## 개요

사용자가 원하는 헤어스타일 이미지를 업로드하면, 해당 스타일과 유사한 포트폴리오를 가진 디자이너 목록을 추천하는 기능.

## 의사결정 기록

| 항목 | 결정 | 이유 |
|---|---|---|
| MVP 방식 | **태깅 기반** | 데이터 부족 상태에서 벡터 임베딩은 비효율. 태깅은 설명 가능하고 필터링 UX에 유리 |
| v2 확장 | 태깅 + 벡터 하이브리드 | pgvector로 임베딩 레이어 추가, 태그 필터 → 임베딩 정렬 |
| 태그 추출 | Vision AI 자동 태깅 | 수동 태깅의 일관성 문제 해결. 정의된 태그 목록 내에서만 추출 |

## MVP 로드맵

### Phase 1: 태그 체계 설계 (백엔드 없이 가능)

> **공부 키워드**: 택소노미(Taxonomy) 설계, 헤어스타일 분류 체계

- [ ] 헤어 태그 카테고리 정의
  - **길이**: 크롭, 숏, 미디엄, 롱
  - **컷 스타일**: 레이어드, 보브, 쉐기, 울프, 투블럭, 허쉬, 테이퍼
  - **텍스처**: 스트레이트, 웨이브, 컬, 내추럴
  - **톤/색상**: 쿨톤, 웜톤, 뉴트럴 / 블랙, 브라운, 블론드, 애쉬, 레드, 하이라이트
  - **무드**: 클래식, 캐주얼, 모던, 빈티지, 시크
  - **성별**: 남성, 여성, 유니섹스
- [ ] 최종 태그 목록 확정 (30~50개 목표)
- [ ] 태그 데이터 모델 설계 (ERD 반영)

### Phase 2: 데이터 모델 + API 설계

> **공부 키워드**: 다대다(M:N) 관계, REST API 설계, DB 스키마

```
Designer ──< DesignerPortfolio >── PortfolioTag >── Tag
                                                      │
User ──< ImageUpload >── UploadTag ───────────────────┘
```

핵심 테이블:
- `tags` — id, category, name, slug
- `portfolio_tags` — portfolio_id, tag_id (M:N 조인)
- `upload_analyses` — id, user_id, image_url, created_at
- `upload_tags` — upload_id, tag_id, confidence (AI 추출 결과)

### Phase 3: 이미지 → 태그 추출 (AI 연동)

> **공부 키워드**: Vision API (GPT-4o / Claude Vision), 프롬프트 엔지니어링, structured output

- [ ] Vision AI에 이미지 전송 → 정의된 태그 목록 중 매칭되는 태그 반환
- [ ] 프롬프트 설계 (예시):
  ```
  이 헤어 이미지를 분석해주세요.
  아래 카테고리에서 해당하는 태그를 모두 선택하세요:
  - 길이: [크롭, 숏, 미디엄, 롱]
  - 컷: [레이어드, 보브, 쉐기, ...]
  - 톤: [쿨톤, 웜톤, ...]
  JSON 형식으로 반환: { "길이": "미디엄", "컷": ["레이어드"], ... }
  ```
- [ ] confidence score 포함 여부 결정

### Phase 4: 매칭 로직 + 오매칭 방지

> **공부 키워드**: 유사도 점수 계산, Jaccard similarity, 가중치 매칭, 필수 조건 필터링

#### 문제: 단순 태그 카운트의 한계

```
업로드:      브라운, 레이어드, 단발, 웜톤, 캐주얼  (5개)

디자이너 A:  브라운, 레이어드, 단발, 웜톤, 모던   → 4/5 = 80% ✅ 좋은 매칭
디자이너 B:  실버, 레이어드, 단발, 쿨톤, 캐주얼   → 3/5 = 60% ← 색상이 완전 다른데 높은 점수
```

디자이너 B는 "실버 + 쿨톤"으로 업로드 이미지와 인상이 완전히 다르지만,
레이어드/단발/캐주얼이 겹쳐서 60%가 나와버림.

#### 해결책 1: 카테고리별 가중치

모든 태그를 동등하게 보지 않고, 카테고리마다 중요도를 다르게 부여:

```
색상/톤:  가중치 3  (헤어에서 색상은 첫인상을 결정)
컷 스타일: 가중치 2  (형태는 두 번째로 중요)
길이:     가중치 2
텍스처:   가중치 1
무드:     가중치 1
```

```
디자이너 A: 브라운(×3) + 레이어드(×2) + 단발(×2) + 웜톤(×3) = 10점
디자이너 B: 레이어드(×2) + 단발(×2) + 캐주얼(×1)             = 5점
→ 차이가 확 벌어짐
```

#### 해결책 2: 필수 태그(must-match) 필터

특정 카테고리는 일치하지 않으면 아예 후보에서 제외:

```
필수 카테고리: 색상, 톤
→ 업로드가 "브라운 + 웜톤"이면, "실버 + 쿨톤" 디자이너는 후보에서 탈락
→ 나머지 태그로만 점수 계산
```

유저가 "색상은 상관없어요" 토글을 켜면 필수 조건 해제 가능.

#### 해결책 3: 카테고리 내 유사도 매핑

같은 카테고리 안에서 "완전 다름 vs 비슷함"을 구분:

```
색상 유사도:
  브라운 ↔ 다크브라운  = 0.9  (거의 같음)
  브라운 ↔ 블론드      = 0.3  (좀 다름)
  브라운 ↔ 실버        = 0.0  (완전 다름)

톤 유사도:
  웜톤 ↔ 뉴트럴       = 0.5  (중간)
  웜톤 ↔ 쿨톤         = 0.0  (반대)
```

→ 불일치 태그도 0/1이 아니라 유사도 점수를 줌

#### 해결책 4: 유저 확인 단계

AI가 태그를 추출한 후 유저에게 보여주고 **수정 기회를 제공**:

```
추출 결과: 브라운 · 레이어드 · 단발 · 웜톤 · 캐주얼
          [색상은 상관없어요] 토글
          [이 태그로 매칭하기] 버튼
```

유저가 "색상 상관없음"을 켜면 색상 가중치를 0으로 → 의도적인 교차 매칭 허용

#### 적용 우선순위

| 순서 | 해결책 | 난이도 | 효과 |
|---|---|---|---|
| 1 | 카테고리별 가중치 | 낮음 | 높음 — 구현 간단하고 바로 효과 |
| 2 | 유저 확인 단계 | 낮음 | 높음 — 프론트엔드만으로 가능 |
| 3 | 필수 태그 필터 | 중간 | 높음 — 명백한 오매칭 제거 |
| 4 | 카테고리 내 유사도 매핑 | 높음 | 중간 — v2에서 벡터와 함께 도입 |

- [ ] 카테고리별 가중치 테이블 설계
- [ ] 필수 태그 카테고리 결정 (색상? 톤? 길이?)
- [ ] 유저 태그 수정 UI 설계
- [ ] 매칭 점수 = Σ(겹치는 태그 × 카테고리 가중치) / Σ(전체 태그 × 카테고리 가중치)
- [ ] 점수 기준 정렬 후 상위 N명 반환

### Phase 5: 프론트엔드 UI (이 프로젝트)

> **공부 키워드**: File API, presigned URL, 로딩 상태 관리, Zustand

- [ ] 이미지 업로드 컴포넌트 (`ImageUploader`)
  - 드래그앤드롭 + 파일 선택
  - 이미지 미리보기
  - 업로드 진행 상태
- [ ] 태그 분석 결과 표시 (`TagResult`)
  - AI가 추출한 태그 칩 목록
  - 유저가 태그 수정/추가/삭제 가능 (정확도 보완)
- [ ] 매칭 디자이너 리스트 (`MatchedDesignerList`)
  - 기존 `DesignerCard` 재활용
  - 매칭율 표시
  - 매칭 이유 (공통 태그) 표시
- [ ] Discover 페이지에 진입점 추가 (버튼/탭)

## 공부 로드맵 (추천 순서)

### Step 1: 지금 바로 할 수 있는 것
1. **태그 체계 설계** — 엑셀이나 노션에 카테고리별 태그 목록 정리
2. **ERD 설계** — 위 데이터 모델을 기반으로 테이블 관계도 그려보기
3. **Vision API 실험** — ChatGPT나 Claude에 헤어 이미지 넣고 태그 추출 프롬프트 테스트

### Step 2: 백엔드 기초 (API 서버 필요)
4. **REST API 설계** — 엔드포인트 정의 (POST /api/upload, GET /api/match)
5. **DB 선택** — PostgreSQL + Supabase 또는 bkend.ai 같은 BaaS
6. **이미지 저장** — S3/Cloudflare R2 presigned URL 방식 이해

### Step 3: AI 연동
7. **Vision API 연동** — OpenAI GPT-4o Vision 또는 Claude Vision API 호출
8. **Structured Output** — JSON 형식으로 안정적인 응답 받기
9. **프롬프트 최적화** — 태그 추출 정확도 올리기

### Step 4: 프론트엔드 구현
10. **이미지 업로드 UI** — File API, drag & drop
11. **API 연동** — fetch/axios로 백엔드 호출
12. **결과 화면** — 기존 DesignerCard 컴포넌트 활용

### Step 5: 고도화 (v2)
13. **pgvector** — PostgreSQL 벡터 확장 이해
14. **CLIP 모델** — 이미지 임베딩 개념과 cosine similarity
15. **하이브리드 검색** — 태그 필터 + 벡터 정렬 조합
