! 충돌 방지 규칙

  1. main 브랜치에서 직접 작업 금지. 반드시 별도 브랜치를 만들 것.
  2. 본인이 맡은 경로 안의 새 파일은 자유롭게 추가해도 OK.
  3. 본인 경로 밖에 이미 존재하는 공용 파일을 수정해야 한다면, 충돌 가능성이 있으니 조심히 작업! 또는 공유.
  4. 전에 올린 .svg 파일은 public/ 하위에 있음 — 그대로 참조해서 사용.
주의: 공용 컴포넌트, 디자인 토큰, 글로벌 스타일(globals.css), 공유 타입 등은 수정하지말고 사용만!

Git 작업 흐름

1. 작업 시작 전 — main 최신화

git checkout main
git pull

2. 새 브랜치 생성

git checkout -b "브랜치명"

예시: feat/onboarding-designer, feat/style-page

3. 작업 후 push

git push

만약 처음 push라 거절된다면: 

git push -u origin "브랜치명"

4. PR 생성 → 리뷰 → squash merge

  • PR 제목 형식: feat: 디스커버 페이지 맵뷰 추가 같이 커밋 컨벤션과 동일하게.
  • 리뷰어 1명 이상 승인 후 merge.

참고: 브랜치 네이밍

  • feat/<feature> — 새 기능
  • fix/<issue> — 버그 수정
  • chore/<task> — 잡일/설정
